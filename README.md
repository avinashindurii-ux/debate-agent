# Debate Agent

A multi-agent debate system. Give it a topic, and two AI agents argue it out,
one for, one against, while a third agent moderates: catching dodged points,
repeated arguments, unsupported claims, and topic drift as the debate runs.

Built for the Groq API. Output is spoken-style by design (short turns, no
markdown, no jargon) since this started as a text prototype for an eventual
text-to-speech / web version.

## What it does

- **Agent A** argues for the topic, **Agent B** argues against it.
- Each turn responds directly to the opponent's last point before adding
  anything new, no talking past each other.
- **Agent C (Moderator)** reviews every round and:
  - flags if either agent dodged the opponent's point or just repeated
    themselves
  - flags any unhedged statistic, named study, or named source as
    unsupported
  - detects when the debate has narrowed into the same technical
    sub-point for too long, and redirects both agents back to the core
    question with an unused angle to raise
  - nudges (softly, not by force) toward argument dimensions that haven't
    come up yet
- Ends with a short, neutral spoken recap of both sides' core positions.
  No winner is declared, no long report, just a plain wrap-up.

## Setup

```bash
pip install groq
```

Set your Groq API key as an environment variable:

```bash
# Windows (cmd)
set GROQ_API_KEY=your-key-here

# Windows (PowerShell)
$env:GROQ_API_KEY="your-key-here"

# Mac/Linux
export GROQ_API_KEY="your-key-here"
```

Get a key at [console.groq.com](https://console.groq.com).

## Run it

```bash
python debate.py "Should social media platforms be legally required to verify users' age?"
```

Or run it with no arguments and it'll prompt you for a topic:

```bash
python debate.py
```

## Config

Everything tunable lives at the top of `debate.py`:

| Setting | Default | What it does |
|---|---|---|
| `MODEL` | `openai/gpt-oss-120b` | Groq model used by all three agents |
| `ROUNDS` | `4` | Number of back-and-forth rounds |
| `MAX_WORDS_PER_TURN` | `90` | Hard cap per agent turn, keeps it spoken-length |
| `NARROWING_STREAK_LIMIT` | `2` | Rounds of overlap before the moderator redirects |
| `DIMENSION_STALL_LIMIT` | `2` | Rounds with no new angle touched before a soft nudge |

If a model name stops working (Groq occasionally deprecates or renames
models), run `list_models.py` to see what your key currently has access to:

```bash
python list_models.py
```

## How the architecture works

Instead of feeding each agent the full verbatim transcript every round
(which grows the token count linearly and can hit rate limits on longer
debates), each turn gets:

1. A one-sentence summary of every prior round (generated by the
   moderator, reused as memory, no extra API call)
2. The full text of only the opponent's immediately preceding turn

This keeps token usage roughly constant regardless of how many rounds run.

Argument "dimensions" (angles the topic could be argued from, generated
once per topic) are tracked internally by keyword overlap against what's
actually said each round. They're never shown to the user, they just power
the coverage nudges and the redirect mechanism.

## Known limitations

- Topic-narrowing and dimension-coverage detection both use keyword
  overlap, not real semantic understanding. They'll miss a repeated point
  that's rephrased in very different language.
- No fact-checking beyond flagging unhedged specificity, the moderator
  can't verify whether a hedged claim is actually true.
- Single-file, synchronous, no async/parallel calls. A 4-round debate
  makes roughly 12-14 sequential API calls (2 agents + 1 moderator per
  round, plus dimension generation and the closing recap).

## Not built yet (kept in mind for later)

- Web/TTS front end (this was designed with one in mind, the compressed
  context and spoken-length constraints are already TTS-ready)
- Real fact-checking via a research/retrieval step
- Structured per-turn output (claim/rebuttal/counter-rebuttal as data,
  not just prose)

## Website (Streamlit)

`streamlit_app.py` runs the debate in the browser, with each turn appearing as it is written.
It reads `GROQ_API_KEY` from your own terminal, so the key never goes into the code or the repo,
and anyone who runs it uses their own key.

```bash
pip install -r requirements.txt
export GROQ_API_KEY="your-key-here"   # set it for your OS as shown above
streamlit run streamlit_app.py
```

The command line version (`python debate.py "topic"`) still works.
